# すれ違い通信

ニンテンドー DS の「すれちがい通信」を真似た機能。
**同じアプリを入れた人と近くにいると、自動で名刺が交換される。**

サーバー（iCloud）は一切通らない。端末同士が Bluetooth で直接やり取りする。

この文書の主題は「**アプリを開いていないときに、どれだけ取りこぼさないか**」。

---

## 1. 何が渡るのか

| 項目 | 例 |
|---|---|
| 表示名 | たかおか |
| ユーザ ID（ハンドル） | `takaoka_3b` |
| 一言（任意・60 文字まで） | 今日は部活休み |

メッセージ・写真・友達関係・対戦の状態などは**一切渡らない**。
画像も載せない。数 KB でも Bluetooth では往復が増え、すれ違う数秒の間に読み終わらないため。

役割分担をはっきりさせている。

```
Bluetooth = 「出会ったこと」を検出する超軽量プロトコル（数百バイト）
iCloud    = アイコンなどの詳しいプロフィール（後から引く）
```

すれ違った記録は**双方の端末の中だけ**に残る。iCloud には送らない。

---

## 2. 「アプリを開いていない」を 4 つに分ける

ひとくちに「開いていない」と言っても、成功率も打てる手も全く違う。

| 状態 | いまの成功見込み | 効いている仕掛け |
|---|---|---|
| ① アプリ表示中 | 高い（数秒） | 通常のスキャン |
| ② ホーム画面に戻しただけ（suspended） | 中〜高 | Background Modes + イベント駆動の再スキャン + **相手からの書き込み** |
| ③ iOS にメモリから落とされた | 中 | **State Restoration**（システムがアプリを起こし直す） |
| ④ 上スワイプで強制終了 | **ほぼ 0** | 打つ手なし（iOS の決まり） |

④ だけは実装では解決できない。iOS は、ユーザーが明示的に終了させたアプリを
Bluetooth では起こさない。ここは「できない」とはっきり言うべきところ。

②③ は設計で大きく変わる。以下がその中身。

---

## 3. 仕組み

### 3.1 双方向で、しかも「置いていく」

端末は発信側と受信側の両方になる。

```
   iPad A                                  iPad B
 ┌──────────────┐                      ┌──────────────┐
 │ Peripheral   │ ──── 広告(UUID) ────▶ │ Central      │
 │              │ ◀─── 接続 ─────────── │              │
 │  card 特性   │ ───▶ 名刺を読ませる    │              │
 │  drop 特性   │ ◀─── 名刺を置かれる    │              │
 └──────────────┘                      └──────────────┘
```

特性（characteristic）を 2 つ持つ。

| 特性 | 向き | 役割 |
|---|---|---|
| `card`（read） | 相手 → 自分 | 相手の名刺を**読む** |
| `drop`（write） | 自分 → 相手 | 自分の名刺を**置いていく** |

**読むだけにしないのが要点。**
すれ違いは本来ひとつの出来事なのに、電波の上では A→B と B→A の
2 本の独立した試行になる。読むだけだと、A の走査が当たっても B の走査が
当たらなければ、A にしか記録が残らない。背面では走査が大きく間引かれるので、
これは頻繁に起きる。

つないだついでに自分の名刺を置いていけば、**1 本つながった時点で双方に記録が残る**。
背面での取りこぼしを減らす、いちばん効く工夫。

### 3.2 なぜ広告そのものに名刺を載せないのか

iOS はアプリが背面に回ると、広告パケットから独自のデータを落とす。
残るのはサービス UUID だけで、それも「その UUID を明示的に探している iOS 端末」
からしか見えない（オーバーフロー領域）。

だから「広告で見つけて、つないでから交換する」形にしている。
往復は増えるが、**背面同士でも成立する唯一の形**。

### 3.3 State Restoration（③ を拾う）

`CBCentralManagerOptionRestoreIdentifierKey` /
`CBPeripheralManagerOptionRestoreIdentifierKey` を付けておくと、
iOS にメモリから落とされた後でも、近くに相手が現れた時点で
**システムがアプリを起こし直し**、`willRestoreState` で状態を返してくれる。

ただし条件がある。

> **起動のいちばん早い段階で、同じ復元 ID のマネージャを作り直していること。**

ここを外すと、せっかく起こされても「復元先がいない」と判断されて捨てられる。
画面（SwiftUI）の組み立てを待ってから無線を起こす形では、この条件を満たせない。

そこで、無線の生死を画面から切り離した。

```
アプリ起動
  └─ AppDelegate.application(_:willFinishLaunchingWithOptions:)
       └─ StreetPassKit.bootstrap()      ← 無線はここで動き出す
            ├─ StreetPassSettings  入り切り・一言・名刺の控え
            ├─ StreetPassLog       記録（ファイル）
            └─ StreetPassRadio     CoreBluetooth + 復元
  └─ SwiftUI
       └─ AppEnvironment
            └─ StreetPassStore              ← 表示するだけの薄い包み
```

画面が無い状態（バックグラウンドで起こされた直後）でも、
**記録と通知は成立する**。ここが前の版との一番の違い。

あわせて「名刺の控え」を `UserDefaults` に持っている。
起こされた直後に iCloud からプロフィールを読み終えるのを待っていると、
起こされた理由であるそのすれ違い自体を取りこぼすため、
最後に分かっていた名刺で先に走り出し、本物が読めたら差し替える。

### 3.4 走査の仕切り直しは、時計ではなく出来事で

走査は「同じ端末を何度も報告しない」設定で動かす（電池のため）。
その代わり、一度報告された相手は、走査を仕切り直すまで二度と報告されない。

前の版は 90 秒ごとのタイマで仕切り直していた。これは**前面でしか働かない**。
アプリが眠っているあいだタイマは進まないので、
いちばん効かせたい②③でまったく効果がなかった。

いまは出来事で駆動している。

| きっかけ | すること |
|---|---|
| 交換が終わった（成功・失敗どちらも） | 2 秒まとめてから仕切り直す |
| 接続が切れた | 同上 |
| Bluetooth が入った / 復元された | 走査を始める |
| 前面に戻った | 仕切り直す |

これらはすべて、iOS がアプリに実行の機会を与えている瞬間に起きるので、
背面でも働く。

### 3.5 相手ごとのバックオフ

一度失敗したからといって、その相手を諦めない。

| 結果 | 次に声をかけるまで |
|---|---|
| 交換に成功 | 180 秒（同じ人と一緒にいる間、接続を繰り返さないため） |
| 失敗 | 20 秒 → 40 → 80 …（最大 600 秒）|

失敗は相手ごとに数える。A と交換できて C と失敗しても、
D への試行には影響しない。

### 3.6 RSSI は記録するが、判定には使わない

電波の強さは `lastRSSI` / `strongestRSSI` として残すが、
**「近いかどうか」の足切りには使わない**。

RSSI は人の体・壁・端末の向きで簡単に 20dBm 以上変わる。
これで足切りすると、本当のすれ違いを取りこぼす方向に働く。
いま最優先なのは取りこぼさないことなので、判定には入れない。

残す目的は「どのくらいの近さで実際に拾えているのか」を後から確かめること。
十分なデータが取れてから、必要なら判定に使う。

### 3.7 1 回のすれ違いを 2 回と数えない

読む経路と置かれる経路の両方が成立すると、同じすれ違いが 2 回記録されうる。
90 秒以内の再受信は同じ 1 回として扱い、回数も増やさず通知も出さない。

## 4. 検討したが採らなかったもの

### Network.framework / Multipeer Connectivity

近距離の通信としては筋がよく、Apple も新規設計では Network.framework を勧めている。
ただし**この機能の目的には使えない**。

Bonjour / AWDL を使うピアツーピアの探索と接続は、
**アプリがバックグラウンドにあると動かない**。バックグラウンド実行の口が無い。
つまり①では速くなるが、いちばん改善したい②③には一切効かない。

「近くにいることの検出」を背面で成立させられるのは、いまのところ
Core Bluetooth（`bluetooth-central` / `bluetooth-peripheral`）だけ。

将来、名刺より大きなもの（画像など）を交換したくなったら、
**発見は Core Bluetooth、実データは Network.framework**、
という分担はありうる。ただし後者は前面にいる間しか動かない前提になる。

### Live Activity（ActivityKit）

**結論: 成功率は上がらない。ただし④の予防には効く。**

よくある誤解だが、Live Activity は**バックグラウンド実行を与えない**。
ロック画面に出る UI であって、アプリを動かし続ける仕組みではない。
Bluetooth の成功率そのものは 1% も変わらない。

効くのは別の経路。

- ロック画面に「すれ違い通信 ON ／ 今日 3 人」と出ていれば、
  **ユーザーがアプリを上スワイプで終了させにくくなる**。
  ④ は実装では解決できないが、「起こさせない」ことはできる
- すれ違いで起こされたとき、その実行機会に Live Activity を更新できるので、
  アプリを開かずに今日の人数が分かる

コストは小さくない。

- **Widget Extension ターゲットの追加が必要**（Xcode で手作業）
- 追加ターゲット用の Bundle ID と署名が要る
- 主アプリの Info.plist に `NSSupportsLiveActivities`
- iPad のロック画面 Live Activity は iPadOS 17 以降（Dynamic Island は iPad に無い）

いまは入れていない。「pull するだけ」で済む範囲を超えるため。
入れるなら独立した作業として、手順を別に用意する。

## 5. 設定（Apple 側の操作は不要）

Bluetooth のバックグラウンド動作も State Restoration も、
**Info.plist だけで有効になる**。専用の entitlement を持たないので、
Xcode の Signing & Capabilities も Apple Developer サイトも触らなくてよい。

`Config/Info.plist`（リポジトリに含まれているので、pull すれば入る）:

```xml
<key>NSBluetoothAlwaysUsageDescription</key>
<string>すれ違い通信で、近くにいる友達と自動で名刺を交換するために使います。設定で切ることができます。</string>

<key>UIBackgroundModes</key>
<array>
    <string>remote-notification</string>
    <string>bluetooth-central</string>
    <string>bluetooth-peripheral</string>
</array>
```

CloudKit のスキーマ変更も不要（サーバーを一切使わないため）。

## 6. 成功率を測る

「なんとなく動いている」で終わらせないために、数字で見る。

### 画面に出ている指標

すれ違い通信の画面に **「システムに起こされた回数」** がある。
これは State Restoration で iOS がアプリを起こし直した回数。
**閉じている間も動いている、動かぬ証拠**になる。

しばらく使っても 0 のままなら、②③ が成立していない。

### 測り方

2 台で 20 回ずつ、状態を変えながらすれ違って、記録された回数を数える。
（片方をカバンに入れ、もう片方を持って 10m 離れてから近づく、を 1 回とする）

| 状態 | 20 回中 | 備考 |
|---|---|---|
| 両方アプリ表示中 | / 20 | ここは高くて当然 |
| 片方表示中・片方ホーム画面 | / 20 | |
| 両方ホーム画面 | / 20 | **ここが本番** |
| 両方、しばらく放置してから | / 20 | ③ が効いているか |
| 片方を上スワイプ終了 | / 20 | 0 に近いはず（仕様） |

「学校の廊下で 10m すれ違ったとき、何 % 記録されるか」が本当の目標値。

### ログで見る

Console.app で `subsystem:<bundle id> category:streetpass`。

| ログ | 意味 |
|---|---|
| `launched by bluetooth` | Bluetooth に起こされた起動 |
| `restored N peripheral(s)` | 復元された |
| `woken up by bluetooth` | 復元の入り口を通った |
| `read a card over bluetooth` | 相手の名刺を読んだ |
| `received a dropped card over bluetooth` | 相手に名刺を置かれた（②で効く経路）|
| `exchange timed out` | 15 秒で打ち切った |

## 7. うまくいかないときの確認順

1. 2 台とも Bluetooth が入っているか（コントロールセンターの青いアイコン）
2. 2 台とも「すれ違い通信を使う」が入っているか
3. 画面の「いまの状態」が **探しています** になっているか
   - 「Bluetooth の使用が許可されていません」→ 設定 > School Message > Bluetooth
4. 2 台とも**プロフィール（表示名）を設定済み**か。名前の無い名刺は相手側で捨てられる
5. 片方でも**上スワイプで終了させていないか**
6. Console.app の `category:streetpass` を見る

## 8. 残っている課題

- **④ 強制終了後**は打つ手がない。Live Activity による「終了させにくくする」
  が唯一の緩和策
- 名刺の内容は署名していない。同じサービス UUID を実装すれば、他人の名前を
  名乗ることは技術的には可能。身内で使う前提の割り切り。
  必要になったら `UserProfile.publicKey` による署名を足す
- 混雑した場所（多数の端末）での挙動は未検証。同時接続数の上限に当たる可能性がある
