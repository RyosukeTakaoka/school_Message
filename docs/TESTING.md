| # | 操作 | 期待結果 |
|---|---|---|
| 1 | A: 入力欄左の写真アイコン → 写真を選ぶ | 入力欄の上にプレビューが出る |
| 2 | A: 送信 | 吹き出しに写真が出る。半透明の覆いと進捗表示 |
| 3 | | アップロード完了で覆いが消える |
| 4 | B: チャットを開く | 写真が表示される（先にサムネイル） |
| 5 | B: 写真をタップ | 全画面で拡大表示。ピンチとダブルタップで拡大縮小 |

## Scenario D — グループ

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | A: ツールバーの人型 3 つのアイコン | グループ作成画面 |
| 2 | A: 画像を選び、名前「2年A組」を入力 | |
| 3 | A: メンバーを 3 人選択 → 「作成」 | 一覧にグループが追加され、右ペインに開く |
| 4 | A: 「明日の体育祭どうする？」を送信 | |
| 5 | B / C / D: アプリを開く | グループが一覧に現れ、未読が付く |
| 6 | 各自: グループを開く | メッセージが読める。送信者名とアバターが出る |
| 7 | B: 詳細（ⓘ）→ メンバー一覧 | 全員が並び、A に「作成者」と付く |
| 8 | B: 詳細 → 「グループを退出」 | 一覧からグループが消える |

**確認ポイント**:
- 7 で「メンバーを追加」が **A にだけ**表示されること
  （Public Database では作成者しかレコードを更新できないため。UI 側でも制限している）
- **3 のメンバー候補に、友達登録していない相手も出ること。**
  `Friendship` は追加した側にしか作られないため、「相手から追加されて始まった
  チャット」の相手は自分の友達一覧に出ない。それでも会話がある以上は
  グループに入れられる必要があるので、候補は「友達 + 会話がある相手」にしている

| 2 | B: A にメッセージを 3 通送る | |

## Scenario H — 規約への同意

**このシナリオは `AppConstants.Legal.requiresConsent = true` にしたときだけ
確認してください。** 既定値の `false` では同意画面自体が出ません
（プロフィール画面の「規約」から読めることだけ確認できれば十分です）。

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | アプリを新規インストールして起動 | 同意画面が出る。要点 4 つと、規約・ポリシーへのボタンが並ぶ |
| 2 | 「利用規約」をタップ | 全文が開き、最後まで読める。閉じると同意画面に戻る |
| 3 | 同意せずにアプリを終了 → 再起動 | もう一度同意画面が出る（先へ進めない） |
| 4 | スイッチをオンにして「同意してはじめる」 | プロフィール登録（または iCloud の案内）へ進む |
| 5 | 一度アプリを終了 → 再起動 | 同意画面は出ず、そのまま使える |
| 6 | プロフィール → 「規約」 | 利用規約・プライバシーポリシーを読み返せる |
| 7 | `ConsentStore.currentVersion` を変更して再ビルド | 「規約が更新されました」と表示され、再同意を求められる |

**確認ポイント**:
- 同意前は iCloud への接続が始まらない（同意画面で「iCloud にサインインしていません」等が出ない）
- 文字を最大サイズにしても文章が読める（Dynamic Type）

## Scenario I — 送信取り消し

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | A: メッセージを送る | B に届く |
| 2 | A: 自分の吹き出しを長押し | 「送信を取り消す」が出る（相手の吹き出しには出ない） |
| 3 | 選ぶ | 「相手の画面には残ります」という確認が出る |
| 4 | 実行 | A の画面が破線枠の「送信を取り消しました」に変わる |
| 5 | B の画面（開いたまま） | 12 秒以内に同じ表示に変わる |
| 6 | 写真を送って取り消す | 画像が消え、B が既にダウンロード済みでも端末内のキャッシュごと消える |
| 7 | CloudKit Dashboard で該当レコードを見る | `mediaAsset` が空、`payload` が短い暗号文に変わっている |
| 8 | 取り消したメッセージを長押し | メニューが出ない（返信もコピーもできない） |
| 9 | 一覧画面 | 最後のメッセージが「送信を取り消しました」になる |
| 10 | 24 時間以上前のメッセージを長押し | 「送信を取り消す」が出ない |

**確認ポイント**:
- 相手の吹き出しを長押ししても「送信を取り消す」は出ない（他人のメッセージは消せない）
- 送信中（まだ届いていない）メッセージは、取り消しではなく従来どおり「取り消す」でキューから消える

### L-3 切ってあるとき

| # | 操作 | 期待結果 |

## エラー処理の確認

要件 14 に対応する確認です。**必ず実施してください。**

| # | 状況の作り方 | 期待する挙動 |
|---|---|---|
| 1 | 機内モードにして送信 | 吹き出しは「送信中…」。上部に「オフライン」帯 |
| 2 | 機内モードを解除 | 自動で送信され、時刻表示に変わる |
| 3 | 機内モードのまま何度も送信 | すべてキューに積まれ、復帰後に順番どおり送られる |
| 4 | 機内モードで写真を送り、アプリを強制終了 → 再起動 | 送信待ちが残っており、オンラインになると送られる |
| 5 | 動画のアップロード中にアプリを強制終了 → 再起動 | 同上。圧縮済みファイルが残っているので最初からやり直しにならない |
| 6 | 「再送信」を押す | 試行回数がリセットされ、すぐ再送される |
| 7 | 「取り消す」を押す | 吹き出しが消え、ローカルファイルも削除される |
| 8 | 電波の悪い場所で長時間 | 4 回の再送後に「送信できませんでした ［再送信］」が出る |

## 記録すること

確認中に見つけた不具合は、次の形で残すと再現しやすくなります。

```
[シナリオ] C-4
[端末] iPad Air (M2) / iPadOS 18.x / ユーザB
[操作] 動画をタップ
[期待] 再生が始まる
[実際] 進捗が止まったまま
[ログ] Console.app で subsystem = com.schoolmessage.app, category = media
```
