# すれ違い通信

ニンテンドー DS の「すれちがい通信」を真似た機能。
**同じアプリを入れた人と近くにいると、自動で名刺が交換される。**

サーバー（iCloud）は一切通らない。端末同士が Bluetooth で直接やり取りする。

---

## 何が渡るのか

すれ違うと、相手の端末に次の 3 つだけが渡る。

| 項目 | 例 |
|---|---|
| 表示名 | たかおか |
| ユーザ ID（ハンドル） | `takaoka_3b` |
| 一言（任意・60 文字まで） | 今日は部活休み |

メッセージ・写真・友達関係・対戦の状態などは**一切渡らない**。
画像も載せていない。数 KB でも Bluetooth では往復が増え、すれ違う数秒の間に読み終わらないため。
相手のアイコンが要るときは、後から iCloud 側のプロフィールを引く。

すれ違った記録は**双方の端末の中だけ**に残る。
「誰と誰がいつ同じ場所にいたか」はサーバーに集めてよい情報ではないので、iCloud には送らない。

---

## 仕組み

端末は**発信側と受信側の両方**になる。

```
   iPad A                              iPad B
 ┌──────────────┐                  ┌──────────────┐
 │ Peripheral   │ ── 広告(UUID) ──▶ │ Central      │
 │  名刺を持つ   │ ◀─ 接続・読み取り ─ │  探している   │
 └──────────────┘                  └──────────────┘
        ▲                                  │
        └────────── 逆向きにも同時に成立 ──────┘
```

1. `CBPeripheralManager` が固定のサービス UUID を広告し、名刺を読み出せる特性を 1 つ用意する
2. `CBCentralManager` が同じ UUID を探す
3. 見つけたら接続 → 特性を読む → すぐ切る
4. 読めた名刺を端末内の記録に足し、端末内の通知で「○○とすれ違いました」と出す

### なぜ広告そのものに名刺を載せないのか

iOS はアプリが背面に回ると、広告パケットから独自のデータを落としてしまう。
残るのはサービス UUID だけで、しかもそれは
**「その UUID を明示的に探している iOS 端末」からしか見えない**（オーバーフロー領域）。

そのため「広告で見つけて、つないでから読む」形にしている。
往復は増えるが、**背面同士でも成立する唯一の形**。

### 電池を守るための制限

| 仕掛け | 値 | 理由 |
|---|---|---|
| 同じ端末を読み直さない間隔 | 3 分 | 一緒にいる間ずっと接続を繰り返さないため |
| 接続の打ち切り | 15 秒 | つながらない相手を抱え込んで、二度と読まなくなるのを防ぐ |
| 走査の仕切り直し | 90 秒ごと | 重複報告を切っているので、再会はこれで拾う |

## 動く条件と限界（正直なところ）

**動く**

- 双方が同じアプリを入れ、すれ違い通信を**入れて**いる（既定は切）
- 双方が Bluetooth を入れ、Bluetooth の使用を許可している
- アプリが前面にある：**数秒**で見つかる
- アプリが背面にある（ホーム画面に戻しただけ）：探し続けるが、iOS が電池を守るために大きく間引くので **数十秒〜数分** かかることがある

**動かない**

- **アプリを上スワイプで終了させると止まる。** iOS が起こしてくれない
- 端末を再起動した後も、次にアプリを開くまで止まる
- 相手が iPhone / iPad 以外（Android など）

State Restoration（`CBCentralManagerOptionRestoreIdentifierKey`）を入れれば
「システムに落とされた後で復帰する」ところまで面倒を見られるが、
アプリ起動のごく早い段階でマネージャを作り直す必要があり、
いまの起動の組み立て（`AppEnvironment` を SwiftUI 側で作る）と噛み合わないので入れていない。
必要になったらここを直す。

## 設定（Apple 側の操作は不要）

Bluetooth のバックグラウンド動作は **Info.plist だけで有効になる**。
専用の entitlement を持たないので、Xcode の Signing & Capabilities も
Apple Developer サイトも触らなくてよい。

`Config/Info.plist` に入れてあるもの（リポジトリに含まれているので、pull すれば入る）:

```xml
<key>NSBluetoothAlwaysUsageDescription</key>
<string>すれ違い通信で、近くにいる友達と自動で名刺を交換するために使います。設定で切ることができます。</string>

<key>UIBackgroundModes</key>
<array>
    <string>remote-notification</string>
    <string>bluetooth-central</string>
    <string>bluetooth-peripheral</string>
</array>
```

CloudKit のスキーマ変更も不要（サーバーを一切使わないため）。

## 確認のしかた

`docs/TESTING.md` の Scenario L を参照。
手早く見るなら、2 台とも前面に出したまま「すれ違い通信を使う」を入れ、
1m 以内に置いて 10 秒ほど待つ。

うまくいかないときの確認順:

1. 2 台とも Bluetooth が入っているか（コントロールセンターの青いアイコン）
2. 2 台とも「すれ違い通信を使う」が入っているか
3. 画面の「状態」が **探しています** になっているか
   - 「Bluetooth の使用が許可されていません」→ 設定 > School Message > Bluetooth
4. 2 台とも**プロフィール（表示名）を設定済み**か。名前の無い名刺は相手側で捨てられる
5. Console.app で `subsystem:<bundle id> category:streetpass` を見る
